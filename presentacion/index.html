El problema

Una sola linea de reglas mal configuradas expone toda tu base de datos al mundo.

El antipatron allow read, write: if true en Cloud Firestore deja toda la base de datos legible y escribible por cualquier persona en Internet.

Tarjetas de credito, cedulas, mensajes privados — todo accesible sin autenticacion. Es una de las causas #1 de fuga de datos en aplicaciones Firebase.

Los linters existentes solo dicen "esto parece inseguro" — y el desarrollador lo ignora porque no ve el impacto real.

La solucion: loop cerrado de 4 pasos

FUGA no opina: ejecuta el ataque, captura la evidencia, repara y re-verifica.

1

SCAN

Analisis estatico con severidad y puntaje de riesgo. Detecta patrones peligrosos en tus reglas de Firestore.

2

PROVE

Lanza un atacante anonimo y captura el JSON exfiltrable. Muestra los datos reales que se filtrarian.

3

FIX

Genera reglas de minimo privilegio. El LLM propone y el evaluador valida que sean correctas.

4

VERIFY

Re-ataca con el mismo exploit: debe quedar en DENY. Loop cerrado, fuga eliminada.

FUGA prueba con datos reales, no solo advierte. Si el atacante pasa, el fix no se acepta.
PELIGROSO 
// Reglas inseguras (antipatron)
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /{document=**} {
      allow read, write: if true;
    }
  }
}
SEGURO 
// Reglas endurecidas (minimo privilegio)
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId} {
      allow read: if request.auth != null
        && request.auth.uid == userId;
      allow write: if request.auth != null
        && request.auth.uid == userId;
    }
    match /{document=**} {
      allow read, write: if false;
    }
  }
}

Arquitectura y tecnologia

Componentes disenados para ser portables, privados y verificables.

Evaluador propio en TypeScript

Oraculo portatil que decide ALLOW/DENY sin Java ni emulador. Corre en CI y en el navegador.

RAG sobre codigo cliente

Infiere esquema y campos PII de tu codigo. Distingue una fuga en /pagos de una en /logs.

LLM pluggable

Amazon Bedrock (nube) / Ollama (local, privacidad) / plantilla determinista. El LLM propone, el evaluador valida.

Servidor MCP

Tools fuga_scan / fuga_prove / fuga_fix para Kiro, Claude y Cursor. Integra seguridad a media conversacion.
