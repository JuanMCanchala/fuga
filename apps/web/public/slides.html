El problema

La mayoría de apps con IA guardan sus datos
en Firebase o Supabase.

Y una sola regla mal puesta las deja abiertas al mundo. Es la causa #1 de exposición de datos personales en apps vibe-coded.

~70%de apps Supabase sin RLS
~60%filtran API keys en el frontend
// una línea, toda tu base de datos expuesta
allow read, write: if true;
El bug que ningún escáner ve

Fuga entre usuarios (IDOR)

La regla exige estar autenticado, pero no comprueba que seas el dueño. Cualquiera con cuenta lee los datos de los demás.

match /pacientes/{id} {
  allow read, write: if request.auth != null;
}

Un anónimo obtiene DENY, así que todos los escáneres dicen «seguro» y siguen de largo.

FUGA lo prueba con dos cuentas

A Alice es dueña del registro.
M Mallory es otra cuenta cualquiera.
Mallory leyó y modificó el registro de Alice. Fuga probada.
Qué es FUGA

No advierte. Prueba.

Un agente especializado que ejecuta el ataque, te muestra los datos filtrados, genera el fix y re-ataca para confirmar que la fuga se cerró.

Cómo funciona por dentro

Cuatro piezas que nadie más combina

Evaluador propio

Oráculo portátil en TypeScript: ALLOW/DENY sin Java ni emulador. Corre en CI y en el navegador.

RAG de tu código

Sabe que /pagos guarda tarjetas. Nombra el PII concreto que se filtra.

LLM propone, evaluador dispone

El modelo redacta el fix; solo se acepta si el atacante queda en DENY. Cero alucinaciones.

Servidor MCP

Vive dentro de Cursor, Kiro y Claude. Revisa la seguridad mientras programas.
